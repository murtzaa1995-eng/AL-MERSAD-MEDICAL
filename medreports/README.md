# منصة التقارير الطبية — الإصدار 1.0

منصة ويب (Flask + SQLite) تربط **المريض والمستشفى/المركز والطبيب والإدارة**: من تسجيل الطلب ورفع الفحص، إلى قراءة الطبيب وتسليم التقرير للمريض بأمان، مع الجرد المالي.
مبنية على وثيقة «المخطط الكامل لمنصة التقارير الطبية».

## التشغيل السريع
```bash
python -m venv .venv && source .venv/bin/activate      # ويندوز: .venv\Scripts\activate
pip install -r requirements.txt
export ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD='كلمة-سر-قوية'   # اختياري
python run.py                                           # http://127.0.0.1:5000
```
- أول تشغيل ينشئ قاعدة البيانات وأنواع الفحوصات الافتراضية وحساب الإدارة (إن لم تحدد كلمة سر تُطبع في الطرفية).
- بيانات تجريبية: `flask --app run seed-demo` ← `hospital@demo.test` و`doctor@demo.test` وكلمة السر `demo12345`.
- الاختبارات: `python -m unittest discover -s tests -t .`
- Docker: `docker build -t medreports . && docker run -p 8000:8000 -v $PWD/data:/data --env-file .env medreports`

## ما الذي تغطيه المنصة (حسب الوثيقة)
| القسم في الوثيقة | الصفحات / الميزة |
|---|---|
| 1. واجهة المريض | `/order/new` (الاسم الثلاثي، العمر، الجنس، الموبايل، نوع الفحص ← المنطقة، ورقة الطلب، الصور، المعلومات السريرية، السعر من الإدارة، الدفع، زر الإرسال لا يتفعل قبل الدفع، ورقة طباعة فيها QR) |
| 2. المستشفى/المركز | `/h/` لوحة المعلومات، الحجوزات (ورقة حجز بمرجع وQR وشعار وتعليمات)، إضافة فحص جديد، فحوصاتي (جهاز، فحص، منطقة، بروتوكول، صبغة، معلومات سريرية، طبيب مرسل، صور، فحوصات سابقة ← إرسال للطبيب)، التقارير المكتملة، الإحصائيات والجرد، الإعدادات. كل مستشفى معزولة عن غيرها |
| 3. الطبيب | `/d/` يرى فحوصات المستشفيات وأنواع الفحوصات المسموحة له فقط، بدء القراءة (يُقفل على طبيب واحد)، محرر تقرير أو استيراد Word، قالب المستشفى تلقائياً، ختم وتوقيع، اعتماد وإرسال، تصحيح موثق، جرد شهري |
| 4. الإدارة | `/admin/` إضافة/تعديل مستشفى وطبيب (بيانات دخول، شعار، قالب، أسعار خاصة، تفعيل/إيقاف، مستشفيات الطبيب وأنواع فحوصه وأجره، ختم وتوقيع)، أنواع الفحوصات والأسعار، كل الطلبات، الجرد، سجل التدقيق |
| 5. التسليم | `/r/<token>` (QR) أو `/results` برقم الموبايل ← رمز تحقق (OTP) ← عرض التقرير وتنزيله PDF. الجلسة 10 دقائق ثم يلزم تحقق جديد دون حذف التقرير |
| 6. الجرد المالي | مستحق / مدفوع / متبقٍ لكل مستشفى وطبيب، **زر «تم دفع المبلغ»** مع دفع جزئي (الباقي يبقى بالحساب)، جرد المرضى المباشرين، صافي الإدارة، فلترة بالشهر والمستشفى والطبيب |
| 7. الإضافات المقترحة | سجل تدقيق، تنبيهات للطبيب والمستشفى، تصحيح موثق بنسخ، حالات الفحص الست، فصل المدفوع عن المستحق. (DICOM: الرفع والتنزيل مدعومان، العارض المدمج مرحلة لاحقة) |

## القرار المفتوح (القسم 8) — ما اعتمدته
اعتمدتُ **الخيار الثالث (المقترح)**: الإدارة تحدد لكل مستشفى طريقة النشر (تلقائي، أو بعد موافقة المستشفى) من صفحة تعديل المستشفى. المريض المباشر ينشر تقريره تلقائياً. غيّره بسهولة إن قررت غير ذلك.

## افتراضات اتخذتها (راجعها)
- العملة **دينار عراقي** بأرقام صحيحة، والتوقيت بغداد (UTC+3). الإعدادات في `.env`.
- **سعر المريض المباشر** = السعر الأساسي للفحص. **سعر المستشفى** = سعرها الخاص، وإن لم يوجد فالأساسي. **أجر الطبيب** يحدده لكل نوع فحص، ونوع الفحص الذي لم يُحدَّد له أجر لا يراه الطبيب.
- يُسجَّل المستحق (على المستشفى وللطبيب) عند **اعتماد التقرير**، والأسعار تُثبَّت على الطلب لحظتها فلا يغيّرها تعديل الأسعار لاحقاً.
- الطبيب لا يرى رقم موبايل المريض.

## ⚠️ ما يلزم قبل الإطلاق الفعلي
1. **الدفع**: الموجود بوابة **تجريبية** (`PAYMENT_PROVIDER=mock`) لا تسحب مبالغ. اربط بوابة حقيقية في `app/services.py` (`start_checkout` + استدعاء `mark_paid` من webhook البوابة). لا تخزّن بيانات البطاقة عندك أبداً.
2. **الرسائل (OTP)**: الموجود يطبع الرمز في السجل. اربط مزود SMS/واتساب في `send_sms`.
3. عيّن `SECRET_KEY` قوياً، فعّل HTTPS مع `COOKIE_SECURE=1`، عطّل `DEV_SHOW_OTP`.
4. خذ **نسخاً احتياطية** دورية لمجلد `data/` (قاعدة البيانات + الملفات). السجلات طبية حساسة؛ راجع المتطلبات القانونية المحلية لحماية البيانات الصحية.
5. للأحمال الكبيرة انقل من SQLite إلى PostgreSQL (الاستعلامات في `app/db.py` مركزية).
6. التشفير الكامل للملفات في حالة السكون يعتمد على قرص/خادم مشفّر (غير مطبق داخل الكود).
